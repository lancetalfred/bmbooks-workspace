DAILY SALES HOUSEKEEPING
Previous  Top  Next

Important:    Close all windows within Bookscan
         on all terminals before proceeding.

Each day you need to close sales for the day to prepare your banking. If you do your banking more than once a day, you will need to run this process each time.

End of day overview
The end of day process is controlled in the Sales / Daily window and consists of several steps:

Printing the X report
As sales are made during the day the transactions are saved to a file called sales.dbf. The X report or the daily sales Graphic report will get its data from this file.

Closing sales
Closing sales copies all the data from the sales file into a file called psales.dbf and empties the sales.dbf file, ready for the next day's transactions.
Important: to ensure all the day's transactions are completed, all terminals must be set back to the main menu before closing sales. Normal business can resume immediately after the closing is complete – this should be a very short time.

Printing the daily sales and banking reports
The All sales (sales by item) and Cashbook reports use the psales.dbf file for their data.

Posting sales
Posting sales copies the data in the psales.dbf file into the sales history files, specifically saleline.dbf (financial data) and salehist.dbf (item sales). It also updates various summary files including period (usually weekly), monthly and annual sales files. Once these updates are done psales.dbf is emptied.

CLOSING AND POSTING SALES
Open the Daily Sales window from the main menu: click on Sales/Daily.
This window will guide you through the end of day process, remembering where you are up to in the process and ensure that you complete all the compulsory steps.
As you complete each step, the system will display a tick in the checkbox shown against each process.

Step by step guide to end of day processing



Step 1:   Print X reports
·An X report is a summary of the day's takings by transaction type for all registers. The report gets its data from the daily sales table - sales.dbf.  
·You can choose to print the report in summary format or in detail; use the Summary Format check box below the X Report button to set this flag.  
·On the Sales tab of System Options, there are two more options you can set up:  
·Split register takings: setting this flag will report the sales takings for each register.  
·Split store takings: if your store is divided into sections, say General and Children's, you can set the register names in each area to reflect this by adding a prefix, e.g. GReg1, Greg2 and CReg3. With the split store takings flag set, the takings will be subtotaled for each area.  
·At the bottom left of the Daily Sales window there is a checkbox to print this report on the docket printer. Otherwise the report prints to your standard printer.  

You can also run a graphic sales report here.

Step 2:   Close sales
·You will need exclusive access to the sales file to run this short routine. So ensure that all terminals have no Bookscan windows open.  
·Click on the Close sales button.  
·As soon as sales are closed you may begin trading again.  
·The date of the last close is shown below the button.  

Step 3:   Print sales and cash reports
Note that these reports can only be printed after closing sales and before posting!
Click on the appropriate buttons to print the All Sales and Cash Book reports.
All sales report
This report is a list of all the day's sales by item. The data is taken from the psales.dbf table.
You can order the report by either:
·Supplier  
·Sales Department  
Other options are:
·Summary or details format  
·Total on ISBN: when this flag is set the report will show total sales for each product. When not set, each sale it listed.  
·Consignment sales: when set, the report will also include consignment sales.  
·Consolidation (department order only): this special set up is where you have prefixed your department codes by a single letter to split them into groups. In this case, the report is sorted by these groups. E.g. you have departments A100,A101, A102, B100, B101 etc. The report will show all 'A' departments first then 'B's etc, subtotaling on each grouping.  
   
Cash book report
This report is a list of all the day's sales transactions by transaction type. The data is taken from the psales.dbf table.
Options here are:
·Summary or details format  
·A Banking List: with this flag set, the report will also print a banking list showing the cheques taken that day.  
·Split stores: splits the report up in register groups, similar to the X report (see above).  
·Split register takings: setting this flag will report the sales takings for each register.  

Step 4:   Post sales
After reconciling your takings, click on the Post Sales button to conclude the process. The psales.dbf file will be copied into the sales history files and used to update the various summary files including the period, monthly and annual sales files. Once these updates are done psales.dbf is emptied.
