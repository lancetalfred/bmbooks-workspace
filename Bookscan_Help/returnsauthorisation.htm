Customer Returns & Returns Authorisations
Previous  Top  Next

Note this area is only accessible for distributor/publisher configurations. It is not relevant for retailers. The procedures are written for the book and music industry, but can be simply adapted for any industry.

Book publishers and distributors usually sell their new titles to bookshops on a sale or return basis. The bookshops are able to return unsold stock only after a certain period since the release date (say, 90 days) and before a cut off date (say, 270 days after the release date). At some stage, say 180 days after the release date, the title is no longer considered new and moves to the backlist. Bookshop orders for backlist titles will have a different return rule, or may be non-returnable.

The Bookscan program allows you set up your products to handle this customer returns policy model or for variations on it.

We also need to cope with customer returns for other reasons:
·wrongly supplied,  
·supplied damaged,  
·supplied with faulty printing or binding,  
·superseded by a new edition.  

Customer returns - procedures summary

Setting up your customer returns policy
The customer returns policy is set on the Options tab of System Options.


Setting a title's returns status
As titles are created in the New Title window, users should set the Returns Status to either:
·Sale or return  
·Backlist  
·No returns.  
Where the return status is set as 'not set', it is treated the same as backlist titles.

The returns status can be amended in the Extra Fields tab of the Title Master window.

Globally managing return statuses
You can globally manage the return status of your titles in the RA Global Updates window.

Invoicing
As you invoice a customer's order, the returns status of each title at the time of invoice (or picking slip) creation is recorded against the invoice line. When a customer later sends in his returns authorisation request to return this product, it is the return status recorded in the invoice file that determines its eligibility for return, not the title current returns status. This allows you to alter the returns status of a product as it ages from 'sale or return' to backlist.

Returns authorisation
Returns authorisation requests from customers are processed in the Returns Authorisation window. As you enter each line of the request, the product's eligibility for return to checked against the returns policy. The program will advise you where a return is ineligible and you will have the choice of declining the return or authorizing it anyway.
Return request for other reasons such as 'received damaged' can also be processed.
Where the customer does not quote an original invoice number, the program will display all eligible invoices, allowing the operator to choose.
At the end of processing, the program will produce a returns authorisation form and the authorisation will be recorded against the original invoice and the title.
The program will prevent operators from authorising the return of an invoiced line more than once.

Processing credits
When authorised products have been returned to you, you can process the credits without re-keying. In the Order Entry window, on credit mode, you can append the RA into the credit note, amend it as required and post the credit. The credit will be recorded against the original invoice in the invoice lines table, preventing the chance of crediting the item twice.

Customer returns – detailed procedures

Setting up your customer returns policy
The customer returns policy is set on the Options tab of System Options.



The program allows two invoice date ranges:
·'sale or return' items (new releases),  
·'other' (or backlist) items.  
To allow returns on sale or return items, tick the checkbox. Then set the minimum number of days and the maximum number of days.
Similarly, set up returns on other items. If returns are not allowed other than on new releases, leave the second checkbox unticked.
You can also set the number of days after which an RA expires.

Setting a title's returns status
Each title will have one of four return statuses:
·Sale or return  
·Backlist  
·No returns  
·Not set  
Where the return status is set as 'not set', it is treated the same as backlist titles.

When an invoice is created, the current return status of each title is recorded against the invoice line in the invoice table. When a returns authorisation request is processed, it is this return status in the invoice table that is used to check whether a product is eligible for return, not the title's current return status.

The Returns Status is set using the Returns Status combo box in the New Title window and the Extra fields tab of the Title master.



Where the return status is set as 'not set', it is treated the same as a backlist title.

Globally managing return status
As new releases age, you will need to change their returns status from 'new release to 'backlist'. You could just change the setting in the Title Master window. Alternatively you can globally manage the return status of your titles in the RA Global Updates window. The RA Global Updates window is opened from the main menu: Purchasing/ Returns/ Returns authorisation/ Global updates.



When the window opens it will display all new release titles. To change the returns status of a line in the browser, select the new return status from the radio buttons on the left of the window. Now double click on the Ret column of the lines you wish to change. As you double click on a line, its return status will change and it will disappear from the browser.
Faster is to select all the lines in the browser you wish to change, open the context menu (by clicking the right mouse) and select 'Set selected to 'backlist'' (or 'not set' or 'firm sale') from the menu.

Using categories
Using Bookscan categories is a useful way to manage your new releases. Set each month's new release titles to a new Bookscan category – called say, DEC08, JAN09, FEB09, MAR09 etc. As a month's new releases are ready to be removed to the backlist, you can load then into the RA Global Update window by selecting the category using the Load Category combo box in the top left of the window. The browser will fill all the new release titles from that month and you can easily change the status to 'backlist' as outlined above.

Returns authorisation
Returns authorisation requests from customers are processed in the Returns Authorisation window which is opened from the main menu: Purchasing/ Returns/ Returns authorisation/ Returns authorisation.



RA Enquiries
Select a customer in the customer field and the window will display:
·A summary of the customer's outstanding RAs,  
·Their account summary,  
·Two browsers showing their current RAs.  

Actions
·Click on an RA in the top browser to display its lines in the lower browser.  
·You can view their old RAs in the browser by clicking the Show Old (F4) button.  
·If the customer has many RAs, you can type the RA number into the 'Find RA' field and press the enter key, to display that transaction.  
·Clicking the Expand Browser (F7) button will expand the lower browser to show more details.  
·To edit the lines of an RA, double click on it in either browser. The window will change to edit mode. See the Processing returns authorisation requests section below.  
·Using the context menu (shown open in the diagram above) to reprint, cancel or delete selected RAs or RA lines. You can also purge old RAs from here.  
Note: to cancel an RA is flag it as 'no longer valid'. The delete it is to remove the RA completely (and irretrievably) from the RA table.  
·Reprint an RA form by clicking the Print RAs (F6) button. The RA printing parameters window will open, where you can reprint RA by setting a variety of criteria.  


      
Processing returns authorisation requests
With a customer selected in the Returns Authorisation window, click on the New Authorisation (F12) button. The window will now display in RA input mode.



·Enter the barcode of the first line of the RA request. The title details will display jus above the browser.  
·Enter the customer reference number (optional). This number will repeat for subsequent lines.  
·The RA quantity will default to '1'. Amend the quantity if required.  
·Enter the original invoice number which your customer should have provided. If this hasn't been provided, leave the field blank.  
·Select the return reason. The default is 'Sale or return'. Options are:  
oSale or return – returning a product because they could not sell it.  
oDamaged - the product arrived damaged.  
oFaulty - faultily manufactured  
oPicking error - the correct product was invoiced but the wrong product despatched.  
oOrder error – the wrong product was invoiced.  
·Enter any comments you wish e.g. 'Return title page only'.  
·Click on the Save (F12) button.  

If you have entered the invoice number and the return reason is 'Sale or return', the program will check whether the line is eligible for return. If it is eligible, the line is saved to the browser, the edit line will clear and you can enter the next line or finalise the RA.

Invoice selection window
If you have not entered an invoice number or the invoice is not in the eligible date range or the return status of the product was set to 'no returns', the program will open the Invoice Selection window.



The left browser shows all this customer's invoices that have not been credited. Invoices outside of the allowed date range are show in yellow. Eligible lines are white.
The browser on the right shows the invoices you (or the program) have selected for this RA. If you had not entered an invoice number in the edit line, the program will select the oldest invoice (or invoices) for you.
Double click on a line in the right browser to de-select it; the line will move to the left browser.
Double click on a line in the left browser to select it and move it to the right browser.

Quantity fields
·Requested – shows the original RA request quantity.  
·Allow – displays the total quantity for which invoices have been selected in the right browser.  
·Refused - displays the total quantity you have refused to accept.  
·To go – the requested quantity less the quantities allowed and refused.  
To save the line, the To Go quantity must be zero.

The following diagram shows an RA where only part of the request has been allowed:



The customer wants to return 5 copies of this title. Invoices #12300 to #12303 are within the date range but #12359 is not. So the program has selected the four eligible invoices and has shown '4' in the Allow field and '1' in the To Go field.
The operator has clicked on the Refuse These (F7) button, causing the program to set the Refused field to '1' and the To Go field to zero. Because the Refused field is not zero, the operator must choose a refusal reason in the combo box before the line can be saved.

Invoice selection window- other features
·Clicking the Categories (F6) button will display a pop up window listing all categories this title belongs to.  
·Clicking the Histories (F7) button will display a pop up window listing a complete list of all the customer's invoices for this title.  
·Clicking the Clear Invoices (F9) button will clear the 'selected invoices' browser.  
·For picking errors you will need to enter the barcode of the product that was actually sent. This will allow the warehouse to process the return properly.  


Returns Authorisation window - Other features
Not our product
Sometimes a customer's RA request includes a product which you do not supply and so is not in your product master file. In that instance, as the operator enters the product code into the barcode field, a dialogue window will open:



Here you can enter the title and quantity. Clicking Save will add a refusal line to the browser with a refuse reason of "not our publication".

Appending invoices and RAs
If a customer is returning all of an invoice (perhaps an order was invoiced to the wrong customer), you quickly create an RA by appending the original invoice. Select the customer in the Returns Authorisation window, click on the Append Invoice (F8) button. A drop down list will be displayed of that customer's invoices. Select the invoice from the list and all the lines of the invoice will be copied into the browser. Amend any line you by double clicking it in the browser to load it into the edit line. Then finalise the RA in the usual.
You can similarly append an existing RA for a customer by clicking the Append RA (F9) button.

Finalising an RA
After all the lines have been entered, click on the Finalise (F12) button. This will open the RA Finalise window.



Options
·You can select whether to print the RA form now. The program allows you to print by date range, filtered on the operator name, so you can batch print when you are ready to.  
·The expiry date is set using the default number of days entered in System options. You can change the expiry date for this RA by selecting a new date or overtyping the Days field.  
·You can set a contact to display on the RA form.  
·In the Saved Messages combo box, you can select one of your saved RA messages to display on the RA form. The message will display in the multi-line field. See the RA messages section below for creating new messages.  
Click on the Post (F12) button to create the RA.


RA messages
RA messages which can be appended to your RA form are intended for you to write your standard returns conditions etc. You can add or edit these messages in the Saved Messages window which is opened from the main menu: Tables/ Authority tables/ Saved messages.



To add a message:
·Click on the Add Message (F3) button. The header and the message fields will clear.  
·Type the name of the message into the header field. E.g. 'Standard RA conditions'.  
·Type the message in to the multi-lone field. The message can be of any length but remember that there needs to be enough room on the RA form to print it.  
·Click on the Save Message (F3) button to save the message.  

Other features
·Use the Next (F9) and Previous (F8) buttons to scroll through the saved messages.  
·You can hide a message so it will temporarily not be available to operators. This could be handy for say, Christmas messages which you can then 'unhide' in December.  
·Ticking the Show Hidden (F7) checkbox will allow you to view hidden messages.  

Title master
In distributor/publisher configurations, the Details tab of the Title Master window has a returns authorisation field. This displays the number of current, re-sellable RAs for the product. Clicking the corresponding RA button will open the RA tab which has a browser displaying the all current RAs for this product.
Note: that the RA total on the details tab is a total of RAs which can be returned to stock. It does not include RAs for damaged or faulty stock.

Integrity check
Running the Stock Fields option in the Integrity Check window will recalculate RA totals on the title master. Remember that only the total of re-sellable stock will be displayed here. Faulty or damaged goods are not counted.

Processing credits
When authorised products have been returned to you, you can process the credits without re-keying. Open the Order Entry window from the main menu: Sales/ Invoice/ Invoice, credit, approval entry.
·Select the customer in the Customer field.  
·Click on the Credit Note (F5) radio button to switch to credit mode.  
·Click the Save F12 button to open the processing view.  
·Click on the Append (F8) button and select an RA from the drop down box.  



A pop up window will be displayed showing the lines of the RA. Deselect any lines you will not be crediting. You can also double click on the Qty column to overwrite a quantity.
·Click the OK button and the RA will append to the browser.

·Finalise you credit not in the usual way.
